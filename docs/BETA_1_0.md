# Candidata 1.0 — prueba con jugadores

Esta entrega privada permite recorrer Kanto completo. Es una candidata: las
pruebas automáticas no acreditan comprensión, diversión ni funcionamiento en
otro ordenador. No se ha enviado el juego a terceros ni publicado una descarga.

## Sesión propuesta

Usa el ZIP completo en un Windows de 64 bits. No instales Godot. Anota versión,
Windows, CPU, GPU, RAM, resolución, DPI y dispositivo de entrada. Ejecuta
Comprobar-equipo.cmd si hay dudas de arranque; usa un perfil de diagnóstico
separado. El procedimiento y la recuperación están en
[Prueba Windows](PLAYTEST_WINDOWS.md).

1. Sin explicación previa, encuentra Nueva aventura, elige inicial y completa
   una ruta. Anota dónde dudas, qué creías que iba a ocurrir y qué ocurre.
2. Mueve, rectifica antes de actuar, consulta una técnica, cancela y orienta.
   Repite usando únicamente teclado; después ratón. Comprueba que el básico y
   las cuatro técnicas se distinguen, y que el área anticipa aliados afectados.
3. Prueba captura, tienda, objetos, completar nivel, movimientos, PC y volver
   al viaje. No expliques los menús durante la prueba; registra los bloqueos.
4. Cierra y abre a mitad de combate. Compara PS, posiciones, cola, orientación,
   equipo, dinero y movimientos preparados. Guarda una copia antes de actualizar
   reglas. Nunca edites el diario para continuar una sesión.
5. Para la prueba larga, juega rutas, ocho gimnasios, Liga/rival, aves y
   Mew/Mewtwo. Anota semilla, inicial, bajas, gasto, rondas excesivas, pausas y
   recompensa. Una derrota es un resultado válido; registra hasta dónde llegaste.
6. Empieza otra aventura: la colección y los logros deben permanecer; una especie
   obtenida permite elegir la primera forma de su línea al nivel 5. No hereda
   niveles ni objetos de la aventura anterior.

Alterna los tres iniciales entre sesiones. Incluye al menos un jugador que no
conozca el proyecto y otro acostumbrado a RPG tácticos. No se fija una cifra de
participantes como prueba de calidad. La evidencia debe identificar a cada
sesión mediante un alias voluntario, sin datos personales innecesarios.

## Registro

Usa [esta plantilla](PLANTILLA_BETA.md). Para errores, incluye los pasos mínimos,
la expectativa, el resultado y si se repite tras cargar. Adjunta capturas y una
copia voluntaria del guardado; el perfil puede contener el nombre elegido.
No hay telemetría ni envío automático. El creador elegirá el canal de recepción.

| Prioridad | Criterio |
| --- | --- |
| Bloqueante | No arranca, pérdida de partida, combate o progreso imposible de continuar. |
| Alta | Orden equivocada sin aviso, controles inaccesibles, información imprescindible oculta. |
| Media | Demasiadas acciones, pausas repetidas, texto o feedback confuso. |
| Baja | Acabado visual, sugerencia o preferencia sin bloqueo. |

## Cierre hacia 1.0

La candidata no pasa automáticamente a versión pública al superar los scripts.
Revisar los registros humanos y del segundo PC, resolver bloqueantes y fallos
altos reproducibles, reconstruir si cambia el juego y repetir las pruebas
afectadas sobre ese EXE. Verificar documentación, créditos, integridad y alcance
de distribución. El creador decide canal, contacto y fecha de publicación.
